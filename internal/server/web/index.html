Mosso

    Workspaces and chats are saved on this machine and in each persistent sandbox. Claude keeps working in the sandbox when Mosso stops; Mosso catches up when it starts again. A sandbox session lasts at most the workspace's session length; Mosso stops it sooner once it has been idle for the workspace's idle timeout (while Mosso is running). A stopped sandbox keeps its files and resumes on your next message. Terminate deletes a workspace's sandbox; its conversation stays in the history and can be archived. Branches and pull requests stay on GitHub.

    Welcome to Mosso

    A workspace is a GitHub repository checked out on a new mosso/* branch in a Vercel Sandbox, with Claude Code ready to work on it.

    Instructions

    What should Claude work on?

    Claude Code runs in the sandbox, in the repository checkout. Describe a task; follow-ups continue the same conversation. When you are happy, publish the changes as a pull request.

      New workspace

      Agent instructions

      Saved with this workspace and applied to every turn. They guide Claude; they do not replace your messages or lift Mosso's restrictions (Claude still cannot push or use GitHub credentials).

      Sandbox environment

      Prefilled from the section, or the defaults from Settings without one; changes apply to this workspace only. A failing setup script stops the creation and destroys the sandbox.

      Mosso provisions a persistent sandbox (resumed as needed), clones the base branch onto a new working branch, runs the setup script if there is one, and installs Claude Code and the Mosso worker. This takes about a minute plus the setup script; the workspace opens while it is set up, and Claude starts on your first message when it is ready, even if you close Mosso's page. The workspace keeps its model, image, setup script and instructions for its whole life, even if its section changes.

      Create pull request

      Mosso commits the sandbox's changes and pushes the branch to GitHub from this machine; the sandbox never gets your GitHub token. A rebased branch is pushed with --force-with-lease.

      Settings for new workspaces

      The setup script runs with bash -e -o pipefail in the checkout, before Claude starts, and never gets your Claude or GitHub tokens. ~/.local/bin and mise's shims are on Claude's PATH; for anything else, append export lines to $MOSSO_ENV. If it fails, the workspace is not created. All of these are preselected in the New workspace dialog, where you can change them; existing workspaces keep theirs. Mosso saves them in its database.

      New section

      Sandbox environment

      New workspaces in this section start from this configuration; you can change any of it in the New workspace dialog. Each workspace keeps what it was created with: editing or deleting the section never changes existing workspaces, and moving a workspace only changes where it is listed.

      Connect GitHub

      1. Open GitHub to create a token ↗. Mosso's permissions are preselected: Contents and Pull requests: Read and write, with a 90-day expiration.
      2. Under Repository access, choose the repositories Mosso may work on, then click Generate token.
      3. Copy the token and paste it here.
